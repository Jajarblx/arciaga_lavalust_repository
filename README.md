# LavaLust Product Inventory

An authenticated product CRUD application built with LavaLust 4.6.0 for Laboratory Exercise No. 5.

## Features

- Session-based authentication backed by the `users` table
- Protected product routes through `AuthMiddleware`
- Product create, read, update, and delete operations
- Server-side validation for names, prices, and quantities
- MySQL connections through PDO with required TLS and CA verification
- Responsive PHP views

## Requirements

- PHP 7.4 or newer with `pdo_mysql`
- Apache with URL rewriting, or another compatible web server
- MySQL or a managed MySQL service

## Installation

Clone your repository and create a private environment file from the committed example:

```bash
git clone https://github.com/YOUR_USERNAME/YOUR_REPOSITORY.git
cd YOUR_REPOSITORY
cp .env.example .env
```

On PowerShell, use `Copy-Item .env.example .env` instead of `cp`.

Fill in `.env` with your own application URL, application key, database host,
port, database name, username, and password. Never commit `.env`.

The public database CA is committed at `certs/ca.pem`. For managed MySQL,
keep `DB_SSL_MODE=REQUIRED`, `DB_SSL_CA=certs/ca.pem`, and
`DB_SSL_VERIFY=true` unless your provider explicitly requires different values.

## Database setup

- Local MySQL schema: `database/local_setup.sql`
- Managed MySQL schema: `database/aiven_setup.sql`

Both files create the `users` and `products` tables and add sample products.
They contain no database credentials and deliberately do not seed login
credentials.

Create an administrator directly in the `users` table using a password hash
generated by PHP's `password_hash()` function. The application verifies it with
`password_verify()`.

## Application routes

| Method | Route | Purpose |
|---|---|---|
| GET | `/` | Redirect to login or products |
| GET | `/login` | Display the login form |
| POST | `/login` | Authenticate a user |
| GET | `/logout` | End the authenticated session |
| GET | `/products` | List products |
| GET/POST | `/products/create` | Display/create a product |
| GET/POST | `/products/edit/{id}` | Display/update a product |
| GET/POST | `/products/delete/{id}` | Confirm/delete a product |

All product routes require authentication.

## Security

- Secrets are read from the ignored `.env` file.
- `.env.example` contains placeholders only.
- The committed CA certificate is public and contains no private key.
- Database setup scripts contain no service passwords or connection URIs.
- Product mutations use POST requests.
